## A. 要真实服务器才能核实的接口行为

只实测过一台真实服务器 **4.7.11.0**;本地实例 4.9.5.0 的结论不算。核实一律只读、低频、单次。

- **Q11 其余服务器的版本未知。** 结案:`curl -s '<地址>/emby/System/Info/Public' | grep -o '"Version":"[^"]*"'`。
- **Q12 图片端点要不要认证头;`/Users/{uid}/Items` 是否正式支持 `SearchTerm`。** 现在图片一律带头(只经 `PosterImage`);
  `SearchTerm` 官方只列在 `/Search/Hints`,4.9.5.0 可用。结案:4.7 上对同一张图带 / 不带头各请求一次;搜一个词。
- **Q13 `PrimaryImageTag` 与 `ImageTags["Primary"]` 以哪个为准。** 两个都解,后者优先。无害,不急。
- **Q14 混合媒体库(`CollectionType == null`)只显示 `Movie,Series`。** 未在任何混合库上验证。
- **Q15 `MediaSource.LocationType` / `VideoType` 官方 OpenAPI 里没有。** 不解;要按 DVD / ISO 区分前先核实。
- **Q17 `baseURL` 带子路径(反代)时,转码 URL 可能丢掉那一段。** `transcodeURL` 用 `URL(string:relativeTo:)`,以 `/` 开头会替换整个 path。
  服务端的 `TranscodingUrl` 是否已含子路径未知,两种修法互斥,⛔ 不得「两种都试」。结案:配了反代子路径的实例上看 `TranscodingUrl` 形态。
- **Q20 转码 seek 的「停流」只是断开连接 + 发 Stopped。** 服务端 ffmpeg 未必立刻退出。结案:连续拖几次看 Dashboard 转码进程是否回落。
- **Q24 搜名字中间的字搜不到。** 4.9.5.0 上只能词首匹配,Emby Web 同样搜不到,是服务器侧。结案:拿到「别的播放器能搜到」的具体场景再对照。
- **Q27 4.7 上 `/Items/Resume?Recursive=true&MediaTypes=Video` 是否正常。** 若反而变空,先去掉 `MediaTypes`。
- **Q28 4.7 上 `Filters=IsResumable` 带 `ParentId` 是否生效。** 剧集页定位「NextUp → 可续播 → 第一集」的第二步依赖它;
  若被忽略会静默定位到「最近播放的集」。媒体库筛选因此不提供「可续播」。结案:4.7 上进一部看了一半的剧。
- **Q30 片头 / 片尾标记从没在任何服务器上见过。** 只见过 `Chapter`。全部按可选处理;兜底是播放页手动标注
  (`ManualMarkersStore`,同剧共用,覆盖服务端标记)。
- **Q33「移出继续观看」(`HideFromResume`)只在 4.9.5.0 上验证。** 4.7 上若 404,菜单项会报错回滚。
  ⛔ 不要在别人的服务器上真的移出条目,只确认端点存在。
- **Q39 播放上报 `SubtitleOffset` 单位未知,字幕延迟不上报。** 字幕延迟只在客户端生效(mpv `sub-delay`)。
  结案:本地实例上用 Emby Web 调一次字幕偏移,看 `Progress` 请求体里的值与界面「秒」的关系,回填 API_CONTRACT.md 5.1。
- **Q50 批量标记在真实服务器上未验(API_CONTRACT.md 5.8)。** Emby 无批量端点,整季 = 逐条串行写(20 集 = 20 个请求),
  无退避重试。未验:连续写会不会 429;4.7 上分集写入后剧 / 季 `UserData.Played` 汇总是否立即更新。
  结案:本地实例上标一季看请求数与耗时;真实服务器只做一次 2–3 集的小批量。
- **Q51 `ProviderIds.Tmdb` 的实际形态未核实(API_CONTRACT.md 3.4.1)。** 按小写键兼容 `Tmdb` / `tmdb`。
  未验:键名、存在率、是作品级还是单集级 ID(`search/episodes?tmdbId=` 要作品级)。
  结案:本地实例起一台带 TMDB 刮削的库看原文;若是单集级,弹幕降级层改为先取 `SeriesId` 再读剧的 `ProviderIds`。
- **Q52 弹幕指纹的 16 MiB `Range` 请求未在真实服务器验证(`DANMAKU.md` §3.1)。** 未验:`stream?static=true` 是否稳定回
  `206` + `Content-Range`(回 200 会拒绝、退回文件名匹配);认证头是否被接受;慢速服务器上让「正在匹配」多停多久。
  结案:真实服务器上播一集,看诊断日志里 `/match` 的 `fileHash` 是不是真值。

已知限制:

- **平铺目录默认第 1 季**(`BaiduPanMetadataScraper.seasonWhenUnknown`),多季剧平铺会配错季。用季文件夹或 `SxxExx` 命名可避免。

  只有认得出集号的文件才借祖先目录的 id。
- **`status` 只映射 `Ended` / `Released`**(规格无枚举),其余原样显示英文。
- **详情页那一趟没有单独的失败提示**:刮削器失败原因是共用槽位,可能张冠李戴,所以整块隐藏。

## D. 工程与播放内核

- **assrt 偶发返回 `sub.subs` 为字典而不是数组,解码失败。** 面板报「响应格式不对」而不是「没有搜到」。
  猜测是 PHP 把空数组编成 `{}`,⛔ 未证实,不要凭猜测改成「字典也当空」。结案:复现时记下关键词 / 字幕 id,单次请求看原始结构。
- **Q18 hardened runtime 生效时 `MPVPlayer()` 会让进程约 5 秒后死掉。** 无崩溃报告,原因未查明,所以 `ENABLE_HARDENED_RUNTIME = NO`。
  要分发时逐条加 `cs.allow-unsigned-executable-memory` / `cs.allow-jit` / … 实测定位,⛔ 不一次全加就宣布解决。
